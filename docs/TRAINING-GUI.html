Your normal fishing settings remain yours.

Open Start Fishing.cmd. The three main tabs have different jobs:

TabWhat it does
Normal fishingYour existing continuous fishing loop, timing, movement, bait, safety, session, locations, images and loot options. Start fishing runs this loop.
Visual targetingRead-only preview/recording, template setup, and explicitly armed one-shot tests. It does not change the normal fishing backend.
Neural trainingImport reviewed labels, export a dataset, train a detector in a separate process, evaluate it and manage rollback. Training does not click or install a model into the normal fishing loop.

Why there were two sets of variables

The older program uses its Settings object and src/config/config.json. The new task tools used independent versioned JSON profiles so evaluation can prove exactly which settings a model was tested with. That separation should have been explained. It also unnecessarily duplicated the image folder, thresholds and capture area.

Click Use normal fishing settings in Visual targeting to copy an explicit snapshot of your current normal variables. It first reads unsaved edits from the normal controls. A mapping appears underneath:

Your variableTask use
img_dirTemplate folder, using the same original path resolution
match_thresholdDetection confidence
canny_thresholdsTemplate and frame edge preprocessing
area_of_interestRecording rectangle enclosing the original polygon
cast_location, loot_location, timing, bait, splash/bite, safety, sessionStay in normal fishing. Detector training does not cast, move or decide when to loot.

The imported snapshot is saved under data/profiles, leaving your original profile and normal configuration untouched. Import again after changing normal variables. A changed profile has a different hash and requires new evaluation for promotion. Neural weights, labels, epochs, device and dataset splits are new parameters because the original program had no model-training equivalent.

What the network learns

The detector learns to locate a bobber rectangle in a color frame. It does not learn how to cast, which hotkey to use, or when a fish bites. Your existing bite and input code are separate. A few tightly cropped template pictures are useful for normal matching but are not enough to train object detection: training needs full scenes and reviewed boxes, including scenes with no bobber.

Fastest start: one training button

If you have human-reviewed pictures from two or more independent sessions, click Train my reviewed pictures — automatic setup. Confirm the starter download. It fills the profile, model, dataset export, run folder, compute device and first-run hyperparameters automatically. Watch the log below; Cancel training / job stops the owned process.

It trains an initial candidate using five passes at 640-pixel model resolution. Two reviewed sessions provide training and validation only; an independent third session is needed for held-out testing. It never invents labels, changes normal fishing, or activates the model. The completed .pt path appears in the tab.

The reviewer no longer scans every recorded picture on each save. Draw and press Enter to save, N to explicitly mark a negative, Space to skip, and Backspace to undo a box. Unreviewed pictures stay excluded.

Quick start: use the numbered buttons

Neural training now starts with a live progress checklist. If you already recorded pictures, click 2. Label pictures. Enter your name, draw boxes around visible bobbers, then Save boxes → next. Use Explicit negative only for pictures with no listed objects. Skip uncertain or repetitive pictures; you do not have to label every adjacent frame.

Record and label examples from at least three independent sessions with 1. Record another session. Each recording gets a fresh session ID automatically. Then click 3. Prepare training dataset; once export completes, the app selects the exported folder for you. Click 4. Install training support, wait for completion, then 5. Start training. If starter weights are missing, it asks whether to download official weights or select a local file. Nothing is downloaded silently and training never clicks in the game.

Three sessions are the minimum for separate train/validation/test partitions, not a guarantee of accuracy. More independent and varied reviewed examples will be needed for a reliable detector. Evaluate before promotion.

1. Collect full scenes

Choose configs/tasks/fishing-neural-v2.json. Check its allowed game title/executable if your client has a different name. Use Select game window and Use full game area, or import the normal fishing area. Set a dataset such as data/fishing-raw. Use a new Session ID for each independent visit and a new Cast ID for each cast. Click Record 30 seconds and focus the game during the countdown. Cast manually. Capture cannot click.

Collect independent visits with different lighting, other players' bobbers and reflections. Keep the same class vocabulary throughout; the example profile uses class 0 bobber and class 1 loot. Recording frames does not approve their labels.

2. Review and import labels

Inspect recorded PNG files in the dataset's images folder; frame identifiers and image paths are in its manifest.json. Prepare a JSON file of human-reviewed boxes. Coordinates are saved-image pixels, not desktop pixels. Use an explicit empty boxes list for a negative image.

[
  {"frame_id":"FRAME_ID_FROM_MANIFEST","boxes":[
    {"class_id":0,"space":"frame_pixels","x":120,"y":80,"width":18,"height":25}
  ]},
  {"frame_id":"ANOTHER_FRAME_ID","boxes":[]}
]

In Neural training enter your reviewer name, select the raw dataset, and click Import human labels JSON. Use Label pictures to draw boxes directly in the GUI. JSON import is an optional advanced alternative. See labeling conventions. No prediction is automatically treated as a human label.

3. Export independent sessions

Enter a new export folder such as datasets/fishing-v1, then click Export reviewed dataset. Check the job log for completion. It exports only explicitly reviewed frames. Session-level splits keep nearby video frames together so nearly identical images do not leak into validation/test results. Use enough independent reviewed sessions to produce train, validation and test partitions.

After export, set Dataset to datasets/fishing-v1. Click Check training dataset. Fix any reported missing review, class mismatch or split problem before training.

4. Train, with visible parameters

Select your training Python executable. A separate training environment is useful; by default this is the current application environment. Install training dependencies is an explicit network operation in that selected environment, in a cancellable process. It does not start training.

Load training config reads the selected JSON. The visible model, epochs, imgsz, batch and device fields override those values for the next run; seed and other values stay from the file. A new config snapshot is saved per run.

FieldMeaning / why
modelLocal pretrained .pt weights. To allow an official download, explicitly check the download box and use a simple name such as yolo11n.pt.
epochsMaximum passes through the training data. More passes do not guarantee better held-out accuracy.
imgszModel image size. Small bobbers can disappear at low resolution; larger values use more memory.
batchImages per training step; reduce it if memory is exhausted.
devicecpu, or a CUDA device index such as 0 after installing a compatible CUDA-enabled PyTorch runtime. The application does not configure your GPU driver.

Use a new output folder such as runs/fishing-v1. Click Train neural detector. Progress, errors, full log path and exit status appear below. Cancel training / job terminates only the owned process tree. Partial artifacts are not approved models.

5. Evaluate before use

Keep the same exported dataset and profile. Candidate weights is the completed run's fit/weights/best.pt. Training run is its parent run folder containing run.json. Set a different, new output folder such as runs/fishing-v1-evaluation, and click Evaluate candidate.

The evaluation compares neural and template detectors on the same held-out sessions and writes overlays and report.json. Review false detections, small-target misses and click-point errors, as well as precision/recall. Offline timing is not a claim about actual live desktop frame age.

Training and evaluation never auto-promote weights. Registration/promotion still require explicit reviewed evaluation evidence; see model lifecycle commands. Rollback selects only an earlier approved release. Neural previews use approved releases. Normal fishing still uses your original detector/bite loop; training does not silently swap it.
